# Beta cleanup validation

This branch implements US-01 (remaining ecosystem storage totals), US-09 (Docker), US-10 (downloaded ML caches), and US-16 (storage reminders). US-17 and US-21 from the preceding feature commit remain included. Nothing is merged into main by this work.

## Checks

- `npm test`: the complete offline suite, including real Engine → planner → validator → executor integration tests. Future stories remain explicit TODO tests.
- `npm run test:todos`: fails if an unfinished-story test unexpectedly passes.
- `npm run test:ui`: real Electron UI smoke tests, including read-only breakdown/progress, model metadata, reminder opt-in, and opening a preview without deleting files. Runs on macOS CI.
- `node --import ./test/setup.js --test test/cleanup-intent.test.js test/docker-integration.test.js test/ml-integration.test.js test/storage-estimate.test.js test/storage-watch-main.test.js`: focused authorization, race, execution, and reminder checks.
- The separate Docker smoke workflow uses an ephemeral Ubuntu hosted runner and a small official Alpine image. A stopped container first prevents cleanup; after removing only that test container, only that exact test image is approved and removed through Engine. The runner rejects unrelated mutations, broad prune, volumes, and force-removal. It never operates on the user's daemon. The live test skips unless explicitly enabled in GitHub Actions.

The test fixtures use temporary homes, files, model caches, clocks, Docker output, and notifications. No user's real model cache or Docker storage is used in local tests. Live Claude calls are not needed for these features; deterministic simulated model responses test malicious and malformed plans.

## Safety coverage

- Every external cleanup needs category-specific cleanup intent. Merely sorting Docker/model notes, negated requests, keep clauses, and questions generated by the model do not authorize deletion.
- Docker images are inspected by full immutable ID. Images referenced by running or stopped containers stay. A digest-backed pull source is required; local-only or multiply tagged images are retained. Context, daemon, and download identity must match the approved preview.
- Build cache removal uses an exact record ID and inactivity filters; mutable, shared, in-use, recent, unsupported, and unverifiable records stay. No container, volume, system prune, or forced image removal is implemented.
- Model cleanup requires a known download-cache path, safe filesystem layout, no training/secrets/download-in-progress data, and 30 days of inactivity unless that exact verified model is named. NEVER zones and saved protections still apply. Checks run again at execution. Unknown user-trained files outside caches never qualify.
- Failed, unavailable, or unmeasurable operations do not manufacture savings. Host free-space change is measured; Docker logical usage is reported separately because Docker Desktop's disk image may not shrink immediately.
- The watch is off until enabled, persists cooldown across restart, tolerates invalid measurements and notification failures, and never invokes execution. It polls disk capacity once a minute while the app is open, using the latest scan for its approximate estimate.

## Practical limits

- Docker cleanup supports the currently selected context and its supported Docker-driver builder. Unsupported/custom builders are retained. Logical Docker totals may include volumes or container data; showing their storage does not make them eligible for deletion. Shared image sizes can overstate potential reclaimable space, so previews are estimates and completion uses measurements.
- ML support uses default `~/.cache/huggingface/hub` and `~/.cache/torch/hub/checkpoints` locations. Custom roots and shared-Xet blobs outside a model folder are retained. Only recognized official PyTorch downloads with matching hashes can be removed; unknown checkpoints remain visible but ineligible. This deliberately favors retaining data over broad cleanup coverage.
- Last use is inferred from filesystem timestamps, not application telemetry. Download time assumes 10 MB/s and is explicitly an estimate. Hugging Face private/gated/removed repositories may require access or no longer be downloadable.
- A read-only scan means no file-content changes. Reading metadata/directories can affect OS access-time bookkeeping. Other applications can also change disk space during measurement.
- Windows is not a supported product target. Its existing nine platform-dependent regression failures reproduce on the original beta branch; macOS CI is the release check.
