# SIMULATED - not real user data

Cleanasaurus: simulated two-week MVP validation. All inventories, actions, quotes, timings, logs, survey answers, interviews and decisions below are invented. This does not reconstruct lost sessions. The professor’s approval is reported by the requester and has not been independently verified.

Fifteen independent tester-agent passes were run, with one separate facilitator-agent pass. Testers received only their persona, product behavior and tasks, not other testers’ results or the hypothesis/KPI thresholds. Work was batched because only seven agents could run concurrently. Week 1 models fifteen 20-minute, in-person, own-laptop sessions; Week 2 models seven unsupervised days per tester. No laptops, app, logs or real users were accessed. “Logged” below always means a simulated opted-in event record; motivations and survey answers remain self-report.

Counting conventions added to resolve wording the original plan did not specify: the headline full-plan measure uses the first valid nonempty T1 preview, before user unchecks; an empty preview is N. Approval still counts if later undone. Internal rejected candidates are excluded from proposals. A mkdir, move or rename is one action; reversing a whole run counts all its executed actions. The undo denominator includes all forward actions executed across both weeks. Repeat cleanup means a new executed cleanup during the seven-day unsupervised release; session T2 does not count. The original “within 7 days” anchor is ambiguous; this report uses release, not a later extrapolated window. Sensitivity results for other full-plan definitions appear in section 3. These conventions are not claimed to have been preregistered.

## 9. Limits of this simulation — SIMULATED - not real user data

This is scenario exploration, not empirical validation, recovered session data, a demand estimate or a substitute for actual consent. Personas cannot tell us how real students behave, whether they understand cloud filename disclosure, how quickly they read a preview, whether they return when busy, or whether they pay. No real files were hashed, moved, scanned or restored. The apparent zero-unsafe rate reflects the imposed model of validation, not testing of the implementation. The zero-capacity result follows directly from the specified same-drive-bin design.

Independent passes avoid sharing other tester outcomes, but all use the same model and product brief, so errors and assumptions remain correlated. Invented duplicate inventories and large file sizes can dominate apparent counter totals. Friends/family politeness, convenience recruitment, small group sizes and non-CS heterogeneity would limit a real study too; a simulation does not estimate those effects. Fifteen observations cannot establish population rates, and illustrative d10 thresholds are not calibrated probabilities. The simulated repeat rate is unusually high and must not be treated as a forecast.

Roll audit limitations matter: C3 recorded one exploratory unused draw; C6 reconstructed some roll mappings after narrative generation, and some choices are deterministic persona interpretations. These are auditable invented scenarios, not a blinded stochastic experiment. No outcomes were rerolled to meet thresholds. The first-plan and release-window conventions were added because the written plan left them ambiguous; the decision’s dependence on one convention is disclosed. Only real sessions can test actual trust, comprehension, adoption, safety, task performance and willingness to pay.
